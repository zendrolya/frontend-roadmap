## Понятие асинхронности в JS

**Асинхронность** - это способность выполнять задачи, не блокируя главный поток.

```js
console.log("Задача 1");
setTimeout(() => console.log("Задача 2"), 0);
console.log("Задача 3");
```

Вывод:

```bash
Задача 1
Задача 3
Задача 2
```

Порядок выполнения:

1. console.log("Задача 1") — попадает в Call Stack, выполняется
2. setTimeout — попадает в Call Stack, его колбэк отправляется в WebAPI
3. WebAPI ожидает 0ms, затем колбэк попадает в Task Queue
4. console.log("Задача 3") — попадает в Call Stack, выполняется
5. Call Stack пуст → Event Loop проверяет Microtask Queue (если есть)
6. Microtask Queue пуста → Event Loop берёт задачу из Task Queue
7. Колбэк из setTimeout попадает в Call Stack и выполняется

## Event Loop (цикл событий)

**Event Loop** - механизм, который управляет выполнением синхронного и асинхронного кода.

Структура:

| Компонент       | Что делает                                     |
| --------------- | ---------------------------------------------- |
| Call Stack      | Стек вызовов - выполняет синхронный код        |
| WebAPI          | setTimeout, setInterval, fetch, DOM-события    |
| Microtask Queue | Promise.then, queueMicrotask, MutationObserver |
| Macrotask Queue | setTimeout, setInterval, события, I/O          |

Алгоритм `Event Loop`:

1. Выполнить весь синхронный код (пока стек не опустеет)
2. Выполнить ВСЕ микротаски (включая добавленные в процессе)
3. Выполнить одну макрозадачу
4. Снова выполнить все микротаски
5. Повторить

> [!IMPORTANT]
> Микротаски выполняются до полного опустошения очереди, включая те, что добавлены во время выполнения. Только потом берётся одна макрозадача.

```js
console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => {
  console.log("3");
  Promise.resolve().then(() => console.log("4"));
});
console.log("5");

// Порядок: 1, 5, 3, 4, 2
```

Разбор:

1. `1` - синхронно
2. `setTimeout` - колбэк в WebAPI
3. `Promise.then` - колбэк в Microtask Queue
4. 5 - синхронно
5. Call Stack пуст - выполняются все микротаски: 3, затем 4
6. Microtask Queue пуста - берется макрозадача: 2

Асинхронная задача сначала попадает в WebAPI, затем в очередь задач (task queue). Пока есть какие-либо синхронные операции (callback stack занят), асинхронная задача ожидает своего выполнения.

В JavaScript есть две очереди:

- Task Queue (Macrotask Queue) - для setTimeout, setInterval, событий
- Microtask Queue - для Promise.then, MutationObserver, queueMicrotask

Микрозадачи выполняются ПЕРЕД макрозадачами после каждого завершения стека.

## Атрибуты async и defer

- В классическом варианте JS скрипт будет загружаться тогда, когда наступит его очередь в DOM дереве, а затем выполняться, только потом продолжится отрисовка DOM дерева.
- `async` - загрузка скрипта будет происходить параллельно с отрисовкой DOM, затем отрисовка остановится и произойдет выполнение скрипта.
- `defer` - параллельно с отрисовкой DOM дерева загружается скрипт, а выполняется только в конце полной отрисовки DOM дерева.

```html
<p>Содержимое перед скриптом...</p>
<script async src="..."></script>
<p>Содержимое после скрипта...</p>
```

> [!TIP]
> Используйте `defer` для скриптов, которые зависят от DOM или друг от друга.
> Используйте `async` для независимых скриптов (аналитика, реклама).

## Объект Promise

**Promise** - объект для отложенных и асинхронных вычислений.

### Состояния

```js
const promise = new Promise((resolve, reject) => {
  // pending - начальное состояние
  // resolve(value) - fulfilled
  // reject(error) - rejected
});
```

### Методы

```js
const promise = new Promise((resolve, reject) => {});
promise.then((value) => {}); // когда используется then на промисе, то он считается аргументом resolve
promise.catch((value) => {}); // когда используется catch на промисе, то он считается аргументом reject
promise.finally(() => {}); // выполнится в любом случае
```

`then`принимает два аргумента:

```js
promise.then(
  (value) => console.log("Успех:", value),
  (error) => console.log("Ошибка:", error),
);
```

При использовании `return` в `then` возвращается новый промис со своим значением `resolve`.

### Статические методы

```js
Promise.resolve(42); // уже разрешенный промис
Promise.reject(new Error("...")); // уже отклоненный промис
```

Пример:

```js
async function getPictures() {
  return Promise.resolve([{ id: 1, src: "" }]); // Имитация успешного запроса с передачей ожидаемых данных
  // или
  return Promise.reject("Error"); // Имитация неуспешного запроса с передачей текста ошибки
}
```

### Комбинаторы промисов

```js
Promise.all([p1, p2, p3]); // ждет все, отклоняется при первой ошибке
Promise.allSettled([p1, p2, p3]); // ждет все, возвращает статусы
Promise.race([p1, p2, p3]); // первый завершившийся (успех или ошибка)
Promise.any([p1, p2, p3]); // первый успешный, ошибка если все упали
```

Пример:

```js
// all - все или ничего
const results = await Promise.all([fetch(url1), fetch(url2)]);
// Если один упадет - весь Promise.all отклонится

// allSettled - ждет всех, даже с ошибками
const results = await Promise.allSettled([fetch(url1), fetch(url2)]);
// [{ status: "fulfilled", value: ... }, { status: "rejected", reason: ... }]

// race - первый завершившийся
const result = await Promise.race([fetch(url1), fetch(url2)]);

// any - первый успешный
const result = await Promise.any([fetch(url1), fetch(url2)]);
```

## Асинхронные функции

```js
async function getUsers() {
  console.log(1);
  const response = await fetch("https://jsonplaceholder.typicode.com/posts/1");
  const data = await response.json();
  return data;
}

getUsers().then(console.log); // Асинхронная функция всегда возвращает промис
console.log(2); // вывод выполнится до await
```

Порядок вывода: `1`, `2`, `data` - потому что `await` приостанавливает функцию, но не блокирует главный поток.

Обрабатывать ошибки в `await` можно, обернув всю конструкцию в блок `try...catch`:

```js
async function getUsers() {
  try {
    const response = await fetch(
      "https://jsonplaceholder.typicode.com/posts/1",
    );
    const data = await response.json();
    return data;
  } catch (error) {
    console.error(error.message);
  }
}
```

> [!WARNING]
> Если не обработать ошибку в async-функции, она станет unhandled rejection - глобальной ошибкой.

## `setTimeout` и `setInterval`

```js
// setTimeout - один раз
const id = setTimeout(() => console.log("Через 1 сек"), 1000);

// setInterval - повторяется
const id = setInterval(() => console.log("Каждую секунду"), 1000);

// Очистка
clearTimeout(id);
clearInterval(id);
```

## `queueMicrotask`

```js
queueMicrotask(() => console.log("Микротаска"));
Promise.resolve().then(() => console.log("Тоже микротаска"));
```
